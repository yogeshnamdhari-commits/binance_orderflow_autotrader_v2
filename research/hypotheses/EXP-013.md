# EXP-013: Two-Stage Event + Direction Prediction (5min Horizon)

## Status: REJECTED

## Hypothesis

The trade-sign signal (IC ~0.05-0.15) is too weak to overcome execution costs when
applied to all trades. However, at the 5-minute horizon:

- Event rate (|ret| > 4.0 bps): **80.6%** — most 5min forward windows contain economically
  significant moves
- Maximum observed |ret|: 13.90 bps (from 730-day analysis)
- Perfect prediction bound: **+11.77 bps** net (taker cost)
- Required prediction accuracy (taker): 63.1%

If we can predict:
- **STAGE A**: Whether a large move will occur (event prediction)
- **STAGE B**: Direction of that move (direction prediction)
- **Only trade** when both P(event) and P(direction) are high enough

The combined expected value might exceed costs.

## Methodology

1. Used 730-day aggregated trade data (Binance BTCUSDT, 2024-2026)
2. Computed forward returns at horizons: 5s, 10s, 30s, 60s, 5m, 15m
3. Event definition: |future_return| > all-in execution cost (4.0146 bps taker)
4. Stage A: Logistic regression / GBC predicting event occurrence from trade features
5. Stage B: Logistic regression predicting direction from book features (V4 sessions)
6. Economic gate: Position only when P(event) × P(direction) × E[|ret|] > cost + margin
7. Validation: Chronological 80/20 split, purged

## Data Sources Used

- `data/hist/normalized/BTCUSDT/aggTrades/*.parquet` (730 days, 2.2B+ trades)
- `data/live/v4/*/derived_v4.jsonl` (12 sessions, full order book depth)
- `data/live/cost_calibration.json` (measured: 4.0146 bps taker, 2.0 bps maker)

| Horizon | AUC | Accuracy | Directional Profit | Net (maker) |
|---------|-----|----------|-------------------|-------------|
| 60s     | 0.575 | 52.4% | 0.04 bps | -1.96 bps |

**Result**: Book features (qi_l1, mpd_bps, spread_bps) have weak directional
predictability (AUC 0.38-0.58). V4 session data is too short (45 min) and
regime-specific (downtrend) to capture medium-horizon moves.

| Data Source | Horizon | AUC | Accuracy | Required | Gap |

## Root Cause

1. **Trade features have no predictive power for event occurrence**:
   IC(sign, return) = 0.01-0.04 at all horizons. Trade size, momentum, and
   volume imbalance do not predict whether a large move will occur.

2. **Book features have moderate direction prediction (IC ≈ 0.26)**:
   But V4 session data lacks the price movement to validate at 5min horizon
   (max |ret| = 7.84 bps, only 12.7% event rate vs 80.6% in 730-day data).

3. **The two datasets are incompatible**: The 730-day data has the moves but
   no book features; the V4 data has book features but no moves. No way to
   combine them.

4. **Signal degrades with horizon**: The trade-sign IC is 0.12 at 5s but
   only 0.01 at 5min — there's no persistence.

## Conclusion

The two-stage model cannot bridge the signal-cost gap because:

- No available data source provides both book-level features AND sufficient
  price movement at the required horizon
- The achievable accuracy (50-52%) is far below the required 63-77%
- The gap between achievable and required accuracy is 13-34 percentage points
- No feature engineering or model selection can close this gap with the
  current data

**Net expectancy**: -0.1 to -4.1 bps across all configurations
**95% CI**: All negative at every threshold
**Terminal state**: Confirmed NO_DEPLOYABLE_EDGE

## Literature Support

- Cont et al. (2013): Price impact slope inversely proportional to depth —
  explains weak signal in thin markets
- Bouchaud et al. (2009): Order flow correlation vanishes after ~10s —
  explains IC degradation with horizon
- Gould & Bonart (2016): Queue imbalance predicts for large-tick stocks —
  Bitcoin is small-tick, limiting predictability
