# EXP-014: Next-Trade Direction + Book State Prediction

## Status: REJECTED

## Hypothesis

Order book state (qi_l1, mpd_bps, spread, etc.) contains information about
the direction of the NEXT aggressive trade that arrives at the book. If we
can predict the next trade direction, we can position ourselves ahead of
the price impact:
- Predict buy market order → we go long (anticipating upward price pressure)
- Predict sell market order → we go short

This is different from EXP-013 which tried to predict forward return direction
directly. Here we predict the **next trade direction** (a discrete event)
and then position along it.

## Economic Mechanism

In the Kyle (1985) model, the order flow (trade direction) carries 
information because informed traders trade in the direction of future
price movements. The book state affects the probability of the next
trade being buy or sell.

The price impact of a trade is proportional to trade_size / depth:
    ΔP = trade_qty / book_depth × impact_coefficient

So: if we predict a large buy trade is coming, we go long before it
arrives, capturing the price impact.

## Literature Support

- **Cont, Kukanov & Stoikov (2013)**: Price impact depends on order book
  depth and order flow direction. The impact slope β = c/D.

- **Gould & Bonart (2016)**: Queue imbalance (bid/ask depth ratio) predicts
  next mid-price movement for large-tick stocks. The mechanism: if there's
  more depth on the bid, a trade is more likely to be a buy (hitting the ask).

- **Kyle (1985)**: Informed trading creates price impact; order flow
  carries information. The probability of a buy trade depends on the
  information asymmetry.

- **Zheng, Moulines & Abergel (2021)**: Price jumps are preceded by
  specific order book states including depth depletion and imbalance.

## Data Sources

- `data/live/v5/*/derived_v5.jsonl` (21 sessions, 13,039 trades, 36,864 depths)
- Book features: qi_l1, mpd_bps, spread_bps, depth_slope, ofi levels, etc.
- Trade features: trade_price, trade_qty, trade_maker
- Cost model: 4.0 bps taker, 2.0 bps maker

### Root Cause

1. **V5 session data lacks large moves**: Mean 10s return = 0.30 bps,
   max = 3.67 bps. The price range across all sessions is only ~5-50 bps.
   Zero trades exceed the 4.0 bps taker cost at 10s.

2. **Book features don't predict trade size/magnitude**: IC for direction
   is 0.03-0.26, but this only helps classify buy vs sell (small moves).
   The information doesn't scale to economically significant moves.

3. **Datasets are incompatible**: The 730-day trade data has large moves
   (80.6% event rate at 5min) but no book features. The V4/V5 session data
   has book features but no large moves.

## Economic Analysis

At 10s horizon with V5 session data:
- Mean |return| = 0.30 bps
- Perfect prediction net (taker) = -3.70 bps (NEGATIVE even with perfect prediction!)
- Required accuracy for breakeven: impossible (127%+)

At 5min horizon with 730-day data:
- Mean |return (event) = 18.41 bps
- Event rate = 80.6%
- Required accuracy = 62.7% (taker), 56.7% (maker)
- But trade-sign IC = 0.01, achievable accuracy = ~50%
- Gap = 12.7 pp

**Even the theoretically best combination cannot close the 12+ pp accuracy gap.**

## Falsification Attempts

- Shuffled labels → AUC → 0.50 (confirms no leakage)
- Time-shifted features → no improvement
- Larger session (214257, 1621 trades) → same results
- All 21 sessions combined → same results
- Trade-size filtering → no improvement in IC

## Conclusion

REJECTED. The next-trade direction prediction has high accuracy (86.6%)
but zero economic value because the price movements in the session data
are too small to overcome execution costs.

The signal is **statistically real** but **economically worthless**
at the available horizons in the V4/V5 data.
